Algorithms worth knowing

The handful of routines that decide correctness and speed. Each card runs the same logic as the Rust source, on example data.

index/store.rs · plan_reconciliation
Index freshness

Reconciliation merge walk

Discovery and the cache are both sorted by raw path bytes, so one linear walk finds what to embed and what to delete. Change detection is (mtime_ns, size); contents are never hashed.

ranking.rs · Ranker::rank
Ranking

Threshold + bounded top-K heap

Embeddings are unit vectors, so cosine similarity is a plain dot product. Scores below the threshold are dropped. The rest go through a max-heap ordered so its root is the worst kept result, giving O(n log k). Equal scores are ordered by path.

embedding.rs · resize_and_center_crop
Preprocessing

Short-edge resize, centre crop

Matches OpenCLIP evaluation exactly: scale the short edge to 256 with a port of Pillow's fixed-point bicubic filter, crop the centre 256×256 with round-half-to-even offsets, then normalise each channel with CLIP's mean and std into a [3,256,256] tensor.

index/ingest.rs · ingest_into_index
Throughput

Ingestion batching

Images are committed in transactions of 256, so an interrupted run resumes. Each transaction is split into vision runs of 8. A rayon pool owned by this one operation decodes and preprocesses those 8 in parallel. An unreadable or oversized file is skipped; an inference or database error aborts.

model/artifacts.rs · ensure_artifact
Model install

Artifact verification ladder

Three pinned files (INT8 vision model 118.8 MB, FP32 text model 254.3 MB, tokenizer 2.2 MB). The common path skips hashing by trusting a manifest tied to the file's identity. Any doubt falls through to a full SHA-256 check or a fresh download.

model/graph_cache.rs · load_session
Cold start

Optimized graph cache, fail-open

ONNX Runtime's level-3 graph optimisation is slow, so its output is saved under models/optimized/<key>.onnx. The key is a SHA-256 over cache format, model hash, ORT build, optimisation level, provider, OS, arch and CPU features. Any failure falls back to the verified source model.

Sessions, threads and locks

VisionGrep is synchronous. It runs things concurrently with scoped threads and a small rayon pool, and never uses an async runtime.

model/mod.rs · SessionLifetime
Memory

Who keeps which model loaded

Models holds each ORT session as Mutex<Option<_>> and loads it on first use. A one-shot search drops the vision session before loading text to cap peak memory. The server keeps both for the next request.

cli/socket.rs · runtime.rs · ingest.rs
Concurrency

Every thread in the program

  • Server accept loop: waits on a Condvar until fewer than 8 connections are active, then spawns one scoped thread per connection (30 s socket timeouts, 1 MiB request cap).
  • Idle watchdog: when the active count reaches zero, starts a 10-minute timer, then stops the server and wakes the accept loop with a dummy connect.
  • Text preload: at server start, loads the text session if the artifacts are already verified, so the first text query skips model load.
  • Tokenizer loader: TextSession::load parses tokenizer.json on a scoped thread while ORT builds the session.
  • Preprocessing pool: min(cores, 4, files) rayon workers decode and resize images; order and per-file errors are kept.
  • Lock order: the index file lock (<db>.lock, flock) is always taken before a model mutex. Two requests on the same index queue up; requests on different folders run concurrently.

Invariants and contracts

The rules other modules rely on. Each has one owning module.

embedding.rs owns

Unit-norm embeddings

  • NormalizedEmbedding(Box<[f32; 512]>) can only be built normalized.
  • Model output: rejects NaN/∞ and zero norm, then divides by the L2 norm.
  • From SQLite: 2048 little-endian bytes, and the norm must be within 1e-3 of 1.
  • So dot() is cosine similarity.
index/store.rs owns

Index identity

  • user_version = 3. A newer schema is an error and the file is left untouched; an older one is rebuilt.
  • The stored search_root must match, so an index can't be reused for another folder.
  • The image and query contract strings are checked separately. A model change clears only the affected table.
main.rs owns

Exit codes and streams

  • 0 results · 1 searched, nothing ≥ threshold · 2 error.
  • Only results go to stdout. Progress, waits and warnings go to stderr.
  • A broken pipe (| head -1) keeps the search's status.
scan.rs · terminal.rs

Exact path bytes

  • Paths are stored as BLOBs of native Unix bytes and sorted bytewise.
  • Text output escapes control and non-UTF-8 bytes; -0 writes them raw.
  • --json refuses non-UTF-8 paths rather than corrupting them.
artifacts.rs owns

Pinned model contract

  • OpenCLIP ViT-B/32-256 DataComp s34b b86k. Vision is dynamic INT8; the final projection and first block stay FP32.
  • Revisions, sizes and SHA-256s are compiled in.
  • Text is padded to 77 tokens with pad id 0, so EOT pooling matches the reference.
decode/ owns

Bounded decoding

  • Dimensions and estimated working memory are checked before any pixel is decoded: ≤ 100 MP and ≤ 512 MiB.
  • RAW: the largest valid embedded JPEG (≤ 64 MiB), short edge ≥ 256. Container walks cap IFDs and boxes.
  • EXIF orientation is applied before preprocessing.
