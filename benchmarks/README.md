# VisionGrep benchmarks

These development-only tools measure retrieval behavior and end-to-end CLI performance without
adding Python to the shipped VisionGrep binary. All model, dataset, index, cache, raw timing, and
binary paths must point outside the repository. The benchmark workflows use runner caches and
`$RUNNER_TEMP`; `.gitignore` also excludes a local `benchmarks/work/` directory.

## Pinned systems

- VisionGrep baseline: commit `09564b0f03764f4d51852f9c698a78395b0d0bc8` and its pinned Qdrant
  CLIP artifacts.
- rclip: release `v3.3.0`, commit `3dcec2de5e23311473f6fb6433e602aa4f4ca812`.
- DataComp candidate: the exact 256x256 OpenCLIP family used by rclip. Source and conversion
  revisions, sizes, and SHA-256 values are in `retrieval/benchmark_manifest.json`.

`model_contract/verify_reference.py` compares the candidate ONNX artifacts with the pinned original
OpenCLIP safetensors. Rust ignored tests independently verify exact token IDs, text and image golden
vectors, cosine scores, deterministic rankings, threshold decisions, and batched/single parity.

## Retrieval corpus and licensing

`retrieval/prepare_coco.py` materializes rows 0 through 499 of the COCO Caption 2017 validation split
from the immutable Hugging Face dataset revision in the manifest. It retains every image's original
COCO/Flickr license identifier and URL and hashes the downloaded bytes. COCO annotations are CC BY
4.0; individual images retain their listed licenses. Neither images nor annotations generated by a
run are committed.

`retrieval/generate_fixtures.py` adds two deterministic CC0 fixtures for screenshot and text-heavy
queries. `retrieval/query_manifest.json` defines 100 pinned COCO-caption queries, curated object,
attribute, color, scene, activity, count, spatial, screenshot, and hard-negative queries, plus
deliberately absent queries. Every system receives the same corpus and query strings.

## Metrics

`retrieval/evaluate.py` reports Recall@1/5/10, precision@1/5/10, MRR@10, nDCG@1/5/10, absent-query
false-positive rate, positive-query false-negative rate, and coverage/precision points across raw
cosine thresholds. It also reports indexing throughput, SQLite size, novel/cached query latency,
and peak RSS where the runner exposes it. These metrics are corpus-specific. Precision is
conservative because an unjudged COCO image may also be semantically relevant. Raw cosine scores
are similarities, not probabilities or confidences.

The checked-in summary under `results/` is intentionally small. It records the code/model/hardware
contract and aggregate values, never raw per-query logs.

## Phase timing scenarios

`performance/run_scenarios.py` records 21 process-cold samples by default for:

1. installed models with no index;
2. `--no-cache`;
3. an unchanged existing index with a novel query;
4. an unchanged existing index with an exact cached query;
5. an existing index with approximately one percent modified images;
6. models and index absent, only when `--include-network` is requested; and
7. an explicit out-of-tree index against a read-only image tree.

Each invocation writes VisionGrep's phase JSON. The summary reports medians and reports p95 only
with at least 20 samples. GitHub-hosted runners do not expose a safe filesystem-cache eviction API,
so those runs are labelled filesystem-cache warm/uncontrolled rather than filesystem-cache cold.
The network scenario is kept separate because transfer time is variable.

## Reproduction

The manual workflows are the canonical commands because they provide isolated Linux or real Apple
Silicon runners with read-only repository permissions. A local remote/cloud runner can reproduce the
corpus and candidate run as follows (paths shown are deliberately outside the checkout):

```sh
python benchmarks/retrieval/prepare_coco.py \
  --output "$RUNNER_TEMP/visiongrep-coco" --count 500 --workers 8
python benchmarks/retrieval/generate_fixtures.py \
  --output "$RUNNER_TEMP/visiongrep-coco/images"

cargo build --release
python benchmarks/retrieval/run_visiongrep.py \
  --binary target/release/visiongrep \
  --corpus-dir "$RUNNER_TEMP/visiongrep-coco/images" \
  --corpus-manifest "$RUNNER_TEMP/visiongrep-coco/corpus.json" \
  --query-manifest benchmarks/retrieval/query_manifest.json \
  --output "$RUNNER_TEMP/datacomp.json" \
  --cache-home "$RUNNER_TEMP/visiongrep-cache" \
  --system visiongrep-datacomp --commit "$(git rev-parse HEAD)" \
  --model-contract openclip-vit-b-32-256-datacomp-s34b-b86k-v1 \
  --index-path "$RUNNER_TEMP/datacomp.db" \
  --timing-dir "$RUNNER_TEMP/datacomp-timing"
```

Run the pinned rclip adapter and evaluator with:

```sh
python benchmarks/retrieval/run_rclip.py \
  --rclip-source "$RUNNER_TEMP/rclip" \
  --artifact-dir "$RUNNER_TEMP/rclip-artifacts" \
  --data-dir "$RUNNER_TEMP/rclip-data" \
  --corpus-dir "$RUNNER_TEMP/visiongrep-coco/images" \
  --corpus-manifest "$RUNNER_TEMP/visiongrep-coco/corpus.json" \
  --query-manifest benchmarks/retrieval/query_manifest.json \
  --output "$RUNNER_TEMP/rclip.json"

PYTHONPATH=benchmarks/retrieval python benchmarks/retrieval/evaluate.py \
  "$RUNNER_TEMP/baseline.json" "$RUNNER_TEMP/rclip.json" "$RUNNER_TEMP/datacomp.json" \
  --output "$RUNNER_TEMP/summary.json"
```

The adapter verifies the rclip commit and every model checksum before loading code or weights.
